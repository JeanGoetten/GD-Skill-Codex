FINALIDADE

De catálogo de ideias a infraestrutura de análise.

O projeto não tenta substituir o designer. Ele cria contratos claros para decompor problemas, encaminhar resultados entre análises, separar cálculo de hipótese e registrar o que ainda exige simulação ou playtest.

O princípio central é epistemológico: uma métrica derivada não vira automaticamente uma conclusão sobre a experiência do jogador.

ARQUITETURA

Uma cadeia de análise composável

As tecnologias servem à rastreabilidade, validação e composição — não ao acúmulo de complexidade.

Σ

World Model

Ontologia compartilhada para entidades, ações, estados, regras, objetivos, conhecimento e estado oculto.

→

Typed Handoffs

Adapters transformam saídas de uma skill em entradas explícitas da próxima.

ƒ

Executors

PowerShell executa análises determinísticas e produz claims, métricas, anomalias e limitações.

{ }

JSON Schema

AJV 8 valida world models, contratos, evidências, hipóteses e relatórios.

◎

Evidence Store

Proveniência, confiança e status epistemológico permanecem ligados aos resultados.

◇

Simulation

Simulações são evidência derivada e permanecem separadas de telemetria e playtest.

TUTORIAL

Começando sem conhecimento técnico

Você não precisa saber programação para entender o fluxo. O ponto de partida é descrever o sistema do jogo com objetos observáveis.

01

Descreva o problema

Escreva o que acontece no jogo: quem age, quais recursos existem, quais regras limitam as ações e qual comportamento deseja investigar.

02

Escolha a lente

O Codex encaminha o problema para uma skill especializada, como estados, concorrência, economia, progressão ou espaço.

03

Leia o resultado

Claims e métricas mostram o que foi derivado. Limitações mostram o que ainda precisa de dados, simulação ou teste com jogadores.

Quer executar? Clone o repositório, instale as dependências com npm install e rode npm test. Para o fluxo completo, use os scripts em architecture/.
